# Ultra 本地浏览器隐私助手（Chrome / Edge，MV3）

这是 Windows 客户端的配套扩展，需用户单独安装到实际使用的浏览器配置。它不连接桌面进程、不操作 VPN，不自动打开保护；设置失败不会断开隧道。MV3 本地后台只负责串行读取、应用和撤销设置，避免多个面板竞争管理记录。没有网页内容脚本、主机访问权限、远程代码或遥测，CSP 禁止扩展页面网络连接。Chrome/Edge 109 或更新版本；未在此浏览器版本上提供的 API 会显示不支持。

## 安装与使用

1. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
2. 开启开发者模式，选择“加载已解压的扩展程序”，选中本目录。
3. 点击扩展图标，再打开“保护设置与本地自测”。逐项阅读说明；内容权限可先选择受支持的允许、询问或拒绝模式，以及可选的 HTTPS 站点原点，再审阅确认。输入和选择不会自动应用。
4. 隐私 API 读回值与控制权在本地检查；内容 API 只能抽样查询来源的有效设置，不能统一证明控制权。企业策略、其他扩展和更具体的站点规则可能改变结果。
5. “撤销本扩展覆盖”只清除本扩展的设置层，不写入历史原值覆盖用户的新设置。停用或卸载扩展也会让浏览器移除此扩展的覆盖层。

浏览器隐私设置在关闭扩展面板后仍可持续生效。`storage.local` 保存设置归属、原值、目标值、操作阶段、管理时间，以及用户主动填写的权限规则原点；不读取浏览历史，不保存完整访问 URL、指纹或自测结果，不使用云同步。原点可能揭示用户选择的站点，撤销该项目后会删除其记录。读取与修改设置所需的 `privacy`、`contentSettings` 和本地管理记录所需的 `storage` 是清单中的全部权限。

写浏览器前先保存待完成记录，读回后再标记完成。中断或结果未知时保留记录，不自动重试写入；重新检查后可撤销本扩展覆盖。浏览器报告由本扩展控制但记录缺失时，也可显式释放覆盖。撤销只清除本扩展设置层，不写回历史值；真实 MV3 后台终止/重启及多窗口生命周期仍待隔离浏览器实测。

## 已实现

- 正式 `chrome.privacy` 设置：WebRTC 非代理 UDP 限制、浏览器预测加载、云搜索建议、云拼写、云错误页面辅助、链接审计 ping、Referer、第三方 Cookie，以及版本支持的 Topics/FLEDGE/广告衡量。
- 正式 `chrome.contentSettings` 规则：摄像头、麦克风、网页定位、通知、剪贴板读取和自动多文件下载提供 allow/ask/block 草稿；JavaScript 仅提供 allow/block。摄像头/麦克风的 allow 必须指定明确 HTTPS 原点，不能全站允许。更换原点会替换本扩展同类规则。浏览器不提供的项目会显示不支持；JavaScript 阻止会使许多网站失效。
- 本地可见性自测：实际浏览器返回的时区、语言、平台、屏幕、逻辑处理器、内存估计、WebGL 渲染器；检查 Canvas、字体、音频、WebGPU、WebRTC 接口存在性及当前来源的权限。不会生成稳定指纹、请求 GPS 或建立 WebRTC/STUN 连接。
- 手动链接清理：仅处理用户粘贴的 URL，删除明确列出的已知追踪参数；识别登录、支付、签名等敏感模式后保留原样。预览后才允许复制，不自动重定向，不监听历史。
- 功能和检测项的 `?` 说明支持悬停、聚焦、点击固定、Esc 和外部点击关闭。

## 真实边界

WebRTC 设置限制非代理 UDP，不等于禁用 WebRTC，不保证所有流量都经过 VPN。第三方 Cookie 的浏览器豁免和 Storage Access API 可能仍允许部分访问。内容设置查询使用用户选择的原点或 `https://example.invalid/` 作为本地设置 API 的参数，**不会联网访问它**；这只是一个来源的抽样，无法证明所有站点例外、企业策略、iframe 和第三方上下文一致。实际站点仍应在地址栏权限设置中核验。

自测在浏览器扩展页中执行，扩展来源和普通网页的权限可能不同，不能把扩展页的权限结果代替目标网站。指纹接口存在不表示已发生跟踪；不可用也不证明整机安全。未枚举全部字体、不读取设备序列号或真实 IP，不伪造语言/时区/GPU、不声称任意原生程序受保护。更完整的一致性反指纹需要受支持浏览器自身的保护机制。

链接签名格式不能被通用识别。保守排除只能降低风险，不能保证所有链接语义不变，所以只提供手动预览和复制。清理过程不打开链接；用户应该保留原链接以便兼容性恢复。

本扩展不会禁用安全浏览、恶意网址保护、密码管理器，也不安装根证书、不解密 HTTPS、不清除用户密码或浏览记录。正常配置与隐身/访客/其他配置分别管理，当前实现不声称管理隐身模式。

## 检查

在项目根目录运行 `node browser-extension/tests.cjs`。测试使用内存中的 Chrome API mock，验证控制权、读回失败、管理记录、撤销覆盖及链接清理边界，不修改真实浏览器配置。

`node browser-extension/coordinator-tests.cjs` 以纯内存 mock 检查多面板队列、写盘失败、中断记录、重启恢复和逐 API 模式限制。`node browser-extension/panel-tests.cjs <jsdom模块绝对路径>` 检查扩展/launcher 动态确认、输入、失效状态和帮助。这些测试不等于实际加载扩展、企业策略覆盖、目标网站或 MV3 生命周期已通过。

桌面页面的隔离 DOM 集成测试为 `node browser-extension/ui-tests.cjs <jsdom模块绝对路径>`（jsdom 26.x），覆盖无订阅导航、二次确认、轻提示、写入失败与隧道隔离、检测筛选和未知状态。这不是实际浏览器或 Windows 策略生效测试。

接口依据：[Chrome privacy](https://developer.chrome.com/docs/extensions/reference/api/privacy)、[contentSettings](https://developer.chrome.com/docs/extensions/reference/api/contentSettings)、[ChromeSetting](https://developer.chrome.com/docs/extensions/reference/api/types)。
