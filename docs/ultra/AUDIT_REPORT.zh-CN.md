## 1. 结论与证据等级

当前版本已经建立了重要的隔离边界：普通用户界面与固定操作的管理员助手分开；用户策略与机器策略分开；新增隐私模块不参与隧道启动决策；策略恢复保留外部变更；WFP 模块拥有独立对象；界面没有把过滤器存在直接标为全路径阻断。但它仍是需要实机验收的预览版本，不能表述为“所有应用层隐私保护已完成”。

最优先的分享风险来自继承的诊断包：它会收集网卡和路由信息，而当前脱敏不移除其中的主机名、MAC、IP 等标识；中文界面却称可直接发给客服。这需要用户主动导出并分享才发生，不是自动外传，也不是新增检测接口主动采集的结果。

| 等级或分类 | 本文含义 |
|---|---|
| P1 | 直接影响交付安全或容易诱导用户泄露信息，应优先处理并复核 |

## 2. 已确认的问题与需求缺口

### A01 · P1 · 原诊断包保留机器与网络标识，界面却鼓励直接分享

**分类：确认，继承自上游。第二轮补充：生成的包对本机Users也有读取范围，不仅在用户外发时触发；见核心复核C03。**

- 位置：`internal/daemon/diag_windows.go:5`、`:6` 收集路由表及完整网卡配置；`internal/daemon/diag.go:85` 的 `redactText` 处理 URL、Bearer、凭据键与订阅路径，没有去除普通文本中的主机名、MAC、IP 等字段；`web/dist/i18n.js:28` 的 `logs.diagNote` 为“诊断包里订阅地址已打码,可以直接发给客服”。
- 触发：用户按界面提示导出原诊断包，再将包发送给他人。网卡、路由等文本可能保留本机和局域网的关联信息。URL 主机部分也会被保留，不能把“地址打码”理解成所有标识消失。
- 证据：主审计者通过 Go overlay 向脱敏函数输入虚构的网卡配置文本，确认上述虚构标识仍然保留；没有为此运行真实网卡信息命令或收集实际设备标识。
- 影响：用户可能因“可以直接发给客服”而跳过审阅。没有证据表明本功能自动上传诊断包；风险集中于导出内容与分享提示不匹配。
- 改进：先移除无条件可分享承诺；将诊断导出分为最少必要报告与用户明确选入的网络详情，提供字段/文件级预览。对文本标识使用一致的本次导出占位符，保留排障关联关系，并增加合成主机名、IPv4/IPv6、MAC、网关、DNS、后缀和路径回归用例。
- 验收：分享预览与实际压缩包一致；默认输出不含测试样本中的原始标识；用户能看清仍保留的字段。不得通过关闭日志、破坏必要错误证据或改变隧道行为来“解决”此项。

### A02 · P2 · 刷新失败和状态变化后，旧证据没有明确失效

**分类：确认；部分来源时间模型属于需求缺口。**

- 位置：`web/dist/privacy.js:108` 至 `:117`、`:357` 至 `:365`；扩展 `browser-extension/panel.js:21` 至 `:26`；`internal/detection/report.go:95` 为全部结果统一设置报告生成时间。
- 触发：先成功读取，再使策略、WFP 或检测读取失败；或者报告生成后由其他软件改变设置。旧报告仍被保留，卡片继续显示“策略值已配置”“固定策略值符合目标”或旧过滤器状态，操作按钮仍按旧报告生成。
- 证据：DOM mock 已复现读取错误提示与旧匹配证据同时存在、启用按钮仍可点击。检测刷新同样保留旧结果。扩展也在读取失败后继续展示先前的卡片。
- 影响：错误提示虽存在，但卡片缺少逐项的“历史结果，当前未确认”；统一 `detectedAt` 也不能表达服务状态等证据的真实采集时间。后端仍会校验权限和目标，不能据此推断存在任意写入漏洞。
- 改进：每个证据来源分别记录采集时间、读取是否成功及是否失效。失败可保留历史内容，但状态改为“当前未确认”；写入前重新核对资格。相关设置发生变化后只使相关证据过期，不要把旧快照重新标成刚刚实测。
- 验收：策略、WFP、检测、扩展分别覆盖成功→失败→恢复；时区已有的 `timeReadable` 处理可作为一致性参考。

### A03 · P2 · 管理员助手取消或失联后缺少显式重新授权流程

**分类：确认。**

- 位置：`cmd/godusevpn/app.go:127`、`cmd/godusevpn/privacy.go:33`、`:65`、`:106`；`internal/privacyhost/protocol.go:348`；`web/dist/privacy.js:51`。
- 触发：首次取消 UAC、助手退出、RPC 或心跳超时。启动函数仅调用一次；通信错误会关闭 Client，后续 `hostCall` 继续持有旧对象或空对象。
- 证据：协议 fake 测试确认会话关闭后继续调用得到关闭错误；源码没有公开重连/重新授权入口。DOM mock 确认助手不可用且 WFP 支持时，选择 EXE 后“确认添加规则”仍可点击；界面没有授权按钮。
- 影响：机器策略核对、撤销或程序规则操作只能失败，通常需要重启整个客户端。首次报告早于授权完成时也不会自动反映助手后来已就绪。隧道独立运行的边界仍然成立，不应为此阻止建隧道。
- 改进：显式区分未请求、授权中、已连接、已取消、已失联；提供“授权管理员操作/重新连接助手”。未知结果的写入绝不能自动重试，先重连、核对现状，再允许用户决定。程序规则写按钮应使用真实助手可用状态。
- 验收：同账号与替代管理员账号、取消、超时、助手崩溃、UI 退出和重新授权均有独立结果；界面保持原用户权限，不能重新以管理员运行整个 UI 作为绕过方案。

### A04 · P2 · 扩展多面板并发修改会丢失恢复记录

**分类：确认，已用内存 mock 复现。**

- 位置：`browser-extension/core.js:38` 至 `:40`、`:62` 至 `:66`、`:78` 至 `:84`；每个 `browser-extension/panel.js:2` 创建独立 Engine。
- 触发：复制扩展设置标签页或在不同窗口打开同一页面，同时应用两个项目。两边读取相同旧 `managed`，再各自整体写回。
- 证据：两个 Engine 同时应用预测加载和搜索建议，两个浏览器设置均写成功且仍由扩展控制，但 storage 中只剩一条记录；对丢记录的项目调用 restore 被拒绝。复现没有调用真实浏览器设置 API。
- 影响：该项目不显示撤销按钮，用户只能借助停用扩展等更大范围动作撤销；并发恢复与应用也存在相同的整对象写入竞争。
- 改进：由共享后台统一串行执行修改，或采用可靠的跨页面协调；不能把每个页面的 `busy` 当全局锁。浏览器显示由本扩展控制但 journal 缺失时，应提供可解释的撤销覆盖入口。
- 验收：多页面同时应用不同项、同一项、应用与撤销交错、一个页面关闭或写盘失败，均不能丢失已产生的扩展覆盖归属。

### A05 · P2 · 跨页后确认旧弹窗仍会执行旧页面的写入

**分类：确认，已用 DOM mock 复现。**

- 位置：`web/dist/privacy.js:181` 至 `:203`；`web/dist/app.js:269` 的导航未取消确认框。时区操作在确认后已有 `alive()` 校验，普通策略与程序规则没有。
- 触发：打开普通策略确认框，页面被导航切至检测页，再确认仍留在屏幕上的旧弹窗。托盘导航事件是候选实际入口，但本轮没有操作真实托盘验证该触发路径。
- 证据：DOM mock直接调用导航后，当前页面已是检测中心，确认仍调用旧闭包的 `PrivacyApply`；这是mock跨页复现，不是实际托盘复现。当前检测页面没有刷新，页面级 busy 也不能代表这个旧操作。
- 影响：操作与当前页面状态脱节。**这仍然需要用户确认，不是没有确认就写入。** 已提交操作本身也不能因导航而假装已回滚。
- 改进：导航取消尚未提交的确认；所有确认后、调用写接口前统一检查页面存活与操作上下文。已开始的操作通过全局任务状态和结果提示收尾，使新页面的相关证据失效。
- 验收：确认前导航、确认后导航、快速切页、托盘事件与语言重绘均有确定行为；不能把旧操作结果写入不再关联的页面。

### A06 · P2 · 单条 WFP 删除可能在未知过滤器残留时误报完成

**分类：源码确认；特定损坏场景待专门fake回归与真实受控验收，本轮不声称已动态复现该残留。**

- 位置：`internal/appfirewall/backend_windows.go:267`、`:416`；`internal/appfirewall/manager.go:212`。
- 触发：原属于某规则的过滤器元数据无法解析，但其确定性 GUID 仍属于该规则 ID。snapshot 将其变为没有 `Rule.ID` 的 Unknown；删除和删除后复核只匹配 `Rule.ID`。
- 影响：未知对象可能被保留，单条移除却返回 `State=removed`、`Verified=true`。当前卸载清理最终核对 `UnknownFilters`，可以拦截这种残留；这不修复单条移除的错误结果。
- 改进：结合本模块所有权和该 ID 的确定性键复核删除完整性；无法安全确定归属时保留对象并报告“移除未确认/仍有未知对象”，不能扩大为删除其他模块对象。
- 验收：损坏元数据、缺失字段、未知但键匹配、未知且不匹配、重复与部分对象均有 fake 回归。未知数量必须独立报告，不能依赖固定警告字串识别。

### A07 · P2 · 卸载最后核对后仍有并发写入窗口

## 3. 简洁文案替换建议

本表是候选文案，不表示已修改应用。短文案必须与状态模型一起调整，不能用简短的“已保护”掩盖未知、未覆盖或尚未实测。

| 场景 | 现有表达或问题 | 建议主文案 | 详情中保留 |
|---|---|---|---|
| 原诊断分享 | 订阅地址已打码，可以直接发给客服 | 导出前请检查敏感信息 | 可能含设备与网络信息；脱敏范围及文件列表 |
| 报告顶部 | 多条重复解释检测/隧道边界 | 本地检查，不修改设置 | 只读范围、原客户端外联、未知不等于安全 |
| 策略匹配 | 策略值已配置，待运行时验证 | 已配置，效果待验证 | 证据来源、适用版本、重启/策略页复核 |
| 无有效新报告 | 旧匹配徽标仍像当前结果 | 当前未确认 | 上次结果、上次成功时间、本次失败原因 |
| WFP 安装成功 | 过长徽标与红色 warning | 过滤器已安装，流量待验证 | EXE、模式、安装数量、回环/代理/仲裁边界 |
| WFP 删除成功 | 成功说明显示为红色错误 | 规则已移除 | 只移除本规则；是否仍有未知对象 |
| 未授权 | 机器级修改需要单独授权，但无入口 | 管理员操作未授权 | 授权入口；取消不影响隧道；当前用户操作仍可用 |
| 助手断连 | 多次刷新依旧失败 | 管理员助手已断开 | 重新授权；未知写入结果须先核对，不能自动重试 |
| 发现限制 | 限制 IP 组播 / 广播 | 限制组播和有限广播 | 定向广播、单播发现、蓝牙和系统代发未覆盖 |
| 系统时区 | 主层突出系统 ID | 当前时区：用户可读名称 | 系统 ID、夏令时偏好、浏览器覆盖可能性 |
| 时区已管理 | 本应用已管理，仍需浏览器复核 | 已设置，浏览器待复核 | 当前 ID 已读回，实际浏览器来源仍需检查 |
| 环境字段未读取 | 条目消失 | 本次无法读取 | 未读取的原因和可用设置入口 |
| 文件检查 | 尚未选择文件 | 本次报告未包含文件检查 | 前往数据工具；不否定其他页面已完成的操作 |
| 检测导出 | 导出脱敏报告 | 预览并导出报告 | 完整/筛选范围、字段选择、残留环境信息 |
| 扩展主状态 | 当前读回符合目标 | 设置符合目标 | 控制权、正常配置范围、来源/站点例外 |
| 自动问号 | 大量重复“说明” | 具体项目的作用与限制 | 使用具体 aria-label，不重复完整正文 |

布局优先顺序建议：主要操作和需处理项 → 实际观察结果 → 配置证据 → 完整限制。观察进程权限与助手通道状态各一行即可；不要在每张卡重复整套权限与隧道说明。
