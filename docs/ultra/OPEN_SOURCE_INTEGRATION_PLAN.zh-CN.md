# Ultra 开源能力集成与受控浏览器计划

更新时间：2026-10-26

## 接手后的源码核实修正

本次核查实际 Windows 源码后，**不再采用 locsim 作为可用的 Windows GPS 后端**：其 Windows 路径主要写入自有缓存/注册表，读回没有独立验证 Windows 位置消费者，并存在忽略写入错误和过宽清理的缺陷。下文 2026-10-21 的候选描述是历史计划，不能作为已验证能力或集成许可。固定提交、源文件与正式系统替代路线见 [`qa/GPS_UPSTREAM_REVIEW_2026-10-26.md`](qa/GPS_UPSTREAM_REVIEW_2026-10-26.md)。

用户的 GPS 与开源集成要求继续保留。需要实现真正后端及独立观察，不能通过检查组件自己的 JSON/注册表把模拟位置显示为成功。适配器事务修复与浏览器配置模型是开发进展，不代表这两个整体功能已经交付。

这份计划处理新增需求：引入成熟的开源系统工具、提供可回滚的 GPS/位置模拟、增加内置浏览器，并让浏览器参数可手动设置或生成可复现的配置。它不把“注册表值已写入”当成“所有应用和网页都无法读取”，也不把随机伪造当成匿名保证。

## 1. 能力分层

| 层级 | Ultra 可以交付的内容 | 用户界面状态 | 通过条件 |
|---|---|---|---|
| A 自动可验证 | 受支持 Windows 策略、应用自有数据、浏览器专用配置、隧道状态 | 可应用并读回 | 读回目标值、保存恢复记录、实际来源复核 |
| B 外部组件 | GPS/位置模拟、CEF 等独立组件 | 组件未安装、已安装未授权、已启用、失败 | 来源、许可证、版本、哈希、权限、回滚均可检查 |
| C 浏览器手动配置 | UA、语言、时区、权限、WebRTC、WebGL/WebGPU、Cookie、代理 | 可编辑、可预览、可恢复 | 参数相互一致，并在专用配置中重新读取 |
| D 应用无法统一实现 | 任意原生程序硬件读取、所有网页指纹、IP 归属、物理 GPS 芯片 | 仅说明/引导 | 不显示“已保护”，不阻断隧道，不伪造成功 |

## 2. GPS/位置模拟适配器

已排除 [locsim](https://github.com/itznan/locsim) 作为 Windows GPS 实现：2026-10-26 对固定提交实际 Windows 代码的审查没有找到可靠的系统位置写入与独立观察闭环。替代路线为 Microsoft 正式 GeolocationProvider API（有版本、身份及授权前置）、GNSS 驱动路线或明确标为测试的 Device Portal；需要逐条完成真正后端。不能将缓存读回当作系统 GPS 生效。

Ultra 不直接把第三方二进制塞进安装包。先做 `location-adapter`：

当前仓库已加入 `internal/locationadapter` 的受控边界和模拟后端测试。它只实现组件来源/许可证/版本/哈希检查、管理员门槛、备份、读回和失败回滚；没有把任何未审核的 locsim 二进制接入发布包，也没有提供可伪造的“全应用 GPS 已开启”状态。

1. 启动前检查组件来源、版本、许可证、SHA-256、管理员要求和系统版本；不满足就只显示引导。
2. 用户选择经纬度、地点或 GPX 后展示影响范围：Windows 位置 API、浏览器 DevTools、测试程序；明确哪些程序不会受影响。
3. 写入前创建组件自己的备份；应用、独立读回、冲突检测、恢复必须是一个事务。失败时保留备份，不断开隧道、不回退直连。
4. 默认使用测试/开发模式；生产模式需要用户明确开启并显示“可能被应用识别为模拟位置”。
5. 先在 disposable Windows VPS 验证注册表/传感器回读和 reset，再考虑桌面交互；不在用户本机自动修改。

## 3. 内置浏览器架构

当前 Wails 窗口使用 WebView2 作为 UI。内置浏览器应作为独立的 `browser-host` 子系统，不能把客户端 UI WebView 当成用户浏览器：

- **WebView2/Edge**：Windows 原生可用，使用独立 user-data folder、独立权限和独立代理；运行时版本需要启动时检查。它适合第一阶段交付。
- **CEF/Chromium**：CEF 是 BSD 许可的嵌入式 Chromium 框架，适合作为可选 Chromium 引擎；体积大、需要签名和沙箱验证，不能直接复制现有 WebView2 配置。
- **其他引擎**：Firefox/Gecko 或 QtWebEngine 只在有稳定 Windows 封装、许可证清单和可复现打包后加入。没有安装或未通过哈希检查时不能显示为可选。

2026-10-26 的源码已经增加独立 `browser-host`，使用固定版本 Microsoft WebView2 托管 SDK 和 WinForms；Go 桥只启动固定安装位置且通过清单、ACL 与身份检查的组件。浏览器使用普通用户、独立会话目录、与已认证服务绑定的数字回环 SOCKS5 中继；隧道、服务身份或租约失效关闭窗口，不改变 VPN 状态。支持区域组合、窗口尺寸、预览和固定种子。运行时清单仍单独显示，不能将 Chrome / Edge 的存在当成第二种已集成内核。

宿主静态编译和纯检查已通过，尚须临时 Windows VM 验证真实创建、普通用户身份、ACL、CDP/子 frame、网络、退出和故障关闭。源码实现与运行时验收分别记录；CEF 仍未提供。未验收前不能宣称已达到用户完整浏览器目标。

浏览器配置结构固定为：`engine`、`profileDirectory`、`proxy/tunnelBinding`、`permissions`、`webrtc`、`webgl/webgpu`、`language/locale/timezone`、`userAgent/clientHints`、`cookie/storage`、`randomizationSeed`。每个字段都要显示来源、影响、是否支持和恢复方式。

## 4. 手动与随机浏览器参数

- 手动模式允许填写 UA、语言、地区格式、时区、Accept-Language、权限默认值、WebRTC 非代理 UDP、WebGL/WebGPU、Cookie、DoH/代理等支持的字段。
- 随机模式使用用户选择的固定种子，生成同一浏览器配置内相互一致的语言、时区、UA、Client Hints 和屏幕尺寸；“重新随机”必须生成新配置并明确会增加独特性风险。
- GPU 新增要求以 H31 为准：提供 WebGL 厂商/渲染器成对预设、手填和固定种子选取；WebGPU 单独控制并读回。修改网页可见字符串不等于修改物理设备、渲染能力、像素或性能。实现层次、子 frame/Worker 覆盖与未知结果要在界面说明；不能以某个读回成功推断全部 GPU 指纹已隐藏。CPU、内存、字体、Canvas/Audio 等仍分别推进实际实现与验证，不作为这一项的隐含完成。
- 所有配置先预览，再启动专用浏览器；不触碰用户现有 Chrome/Edge 配置，不清理用户已有 Cookie，不自动登录或上传指纹。

## 5. 系统层开源组件准入

任何新增组件都必须提交：上游 URL、许可证、版本/tag、SHA-256、构建方式、依赖许可证、默认联网行为、管理员权限、卸载方式、回滚测试和替代方案。没有这些证据的仓库只能列入路线图，不能被下载后直接执行。

### 当前候选矩阵

| 候选 | 计划用途 | 许可证/来源 | 集成边界 | 当前决定 |
|---|---|---|---|---|
| [locsim](https://github.com/itznan/locsim) | 曾计划用于 Windows 位置 | 固定提交实际源码审查见 GPS 报告 | Windows 路径无法形成可靠系统写入/观察闭环 | 已排除；不能按 README 宣称集成可用 |
| [Microsoft WebView2 SDK](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.4314.35) | 独立 Windows 浏览器宿主 | 固定 1.0.4314.35、SHA-256 和 SDK LICENSE | 普通用户、独立数据、固定 SOCKS5 绑定、租约和导航门控 | 已编译源码；真实宿主、GPU、网络组合仍待 VM |
| [CEF](https://github.com/chromiumembedded/cef) | 可选 Chromium 内置浏览器引擎 | CEF 框架常用 BSD；Chromium/第三方依赖为多许可证，需完整 SPDX/SBOM、NOTICE/依赖清单 | 独立 profile、沙箱、签名、升级和代理绑定；不能继承客户端 WebView 状态 | P3/P4 评估，未提供时不显示可选项 |
| [uBlock Origin](https://github.com/gorhill/uBlock) | 用户主动安装的网页请求/跟踪拦截扩展 | GPL-3.0 | 只在用户选择的真实浏览器 profile 内运行；显示权限、规则来源和更新状态 | 可选扩展候选，不静默安装，不当作系统级保护 |
| Windows WFP/隐私策略/时区 API | 指定 EXE 规则、系统设置和回读 | Windows 官方接口，不是额外第三方常驻工具 | 固定动作映射、目标范围、备份和独立读回 | 优先使用现有实现，不为引入依赖而引入依赖 |

### 明确不作为“开源组件即解决”的项目

- 全系统硬件噪音、GPU/设备序列号、MAC 地址和字体列表的统一伪造：没有可靠的单一用户态开源组件可以对所有原生程序和网页同时生效；检测中心只报告可观察范围。
- 全局 GPS 隐身：位置模拟只影响支持 Windows Location Provider、测试覆盖或浏览器 DevTools 的消费者；GeoIP、Wi-Fi、账号历史和物理 GPS 仍单独报告。
- 任意应用端口扫描：WFP 可做指定进程规则，但不能在不破坏系统通信、回环和代理代发的情况下保证所有应用行为都被同一个开关覆盖。
- 通过 DLL 注入、任意脚本或未知代理“修复指纹”：这类方案会扩大权限和泄露面，不能进入默认安装包。

## 6. 里程碑与验收

1. **P1 文案与模型修复**：所有不可实现项改为“仅说明/需组件/需浏览器设置”，检测中心动作必须能跳到实际入口；不能执行的动作不显示“启用”。已完成运行时清单 MVP 和对应 UI 说明。
2. **P2 GPS 适配器**：组件发现、许可证/哈希、备份、apply/readback/reset、冲突和失败隔离；Windows VPS 往返测试。
3. **P3 WebView2 专用浏览器**：独立 profile、引擎/版本显示、代理绑定、权限面板、参数预览、固定种子随机配置、退出清理选项。
4. **P4 CEF 可选引擎**：仅在构建产物、沙箱、签名、升级和资源体积门槛通过后加入；未通过则保留 WebView2。
5. **P5 实测与路线图审计**：真实 Windows VPS 验证浏览器来源、WebRTC/WebGPU/Canvas/语言时区、GPS 组件回滚、隧道断开错误恢复、普通用户/UAC、WFP/流量。当前 `v0.01-beta` 只按已实现的现有功能验收和发布；GPS、CEF、uBlock、独立浏览身份等完成后再进入后续版本或在用户明确扩大 beta 范围后重新设定门槛。

每个里程碑都要记录预期、实际、偏差、恢复、未验证范围和下一步；任何失败都不能自动关闭隧道或回退直连。
