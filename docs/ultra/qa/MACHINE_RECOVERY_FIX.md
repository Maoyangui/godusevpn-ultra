# A13 / C06：机器策略恢复与备份权限修复

2026-10-19，Ultra 副本。本记录对应本轮源码和无真实注册表写入的测试，不把 fake 令牌或临时目录 ACL 验证当作实际 SYSTEM / VPS 恢复验收。

## 执行范围

`privacy.NewMachine` 使用独立的机器上下文、注册表写入口和文件存储。它只接受 catalog 中四项 Windows 机器策略及其精确 HKLM 位置：广告 ID、在线语音、剪贴板历史和剪贴板跨设备同步。应用、回读、单项恢复和批量恢复都要求 Windows 中已提升的进程；SYSTEM 不再需要 Interactive SID，也不会被伪装成普通用户。

机器 backend 的原生写入在每次操作前再次核对实际进程提升状态、固定机器位置和可恢复值格式。它不调用要求交互用户的 HKCU 写入入口。机器环境读取只涉及提升状态、系统版本与固定 HKLM 版本信息，不为取得机器资格读取用户 HKCU 或当前用户绑定。

机器 `Apply` 仍使用原有 SKU / 最低 build 支持条件；不因管理员或 SYSTEM 权限而假定 Server、Home 或旧系统支持正式策略。`Restore` / `RestoreAll` 恢复的是先前已管理的原始值，因此不因当前系统 SKU / build 改变而拒绝；仍必须满足提升权限、机器白名单、受信备份、格式/校验、外部修改冲突保护和写后回读。没有原始记录时不接管外部值。

用户 `privacy.New` 保留 SafeUser 限制。SYSTEM、服务身份、缺少交互身份的进程仍不能通过用户 manager 修改或恢复 HKCU。机器恢复不包含浏览器用户策略、用户时区或其他用户的备份；机器 RestoreAll 也不代表完整卸载、删除 WFP 规则或撤销隧道 guard。原 GUI / CLI / IPC 接口和路径配置没有扩展。

## 机器存储不变量

`NewMachine` 单独绑定机器 lock、durable write、目录验证与 journal 打开方法，不再复用会授予具体用户 SID 的用户 store。

- 生产 helper 仍只从正式 ProgramData 已知目录选择固定产品子目录，RPC 参数和环境覆盖不能选择机器恢复路径。
- 机器目录及其直接文件只允许 SYSTEM / BUILTIN Administrators，owner 也是上述角色。新目录、锁文件、写前临时文件及 journal 在创建时原子使用 `O:BAG:BAD:P(A;OICI;FA;;;SY)(A;OICI;FA;;;BA)`；没有先写私有内容再补 ACL 的窗口。
- 访问前从本地固定磁盘根逐级检查重解析点，拒绝 UNC、设备路径、ADS、非固定盘与非目录祖先。机器目录父级必须由管理员角色拥有且不存在其他主体的写入权限；正式 OS / ProgramData 祖先仍属于安装和核心路径信任边界，本模块不防御恶意管理员更换整个命名空间。
- 读报告不修权限、不创建 journal。目录和所有直接子文件均受检查，包含 lock 与遗留临时文件；不接受意外子目录。文件通过不跟随最终重解析点的句柄检查 owner、ACL、普通文件属性及单一硬链接数，再接受其内容。
- 记录仍在注册表变更之前持久保存，临时文件写入并同步后原子替换；持久化失败阻止新的注册表写入。原值缺失、原类型与字节、外部变更冲突、异常退出待恢复的语义继续保留。

helper 初始化只验证目录及父级，不修复旧目录。完整子对象检查在机器策略 manager 的读写之前执行；单独坏 journal 不应被扩展为依赖独立 WFP 持久库的 FirewallReport / Remove 必须接受该 journal。目录本身不可信时仍拒绝初始化；这不是绕过目录权限检查。

## v1 遗留对象与显式迁移

旧版本可能已经向执行管理员的具名 SID 授予机器目录、journal、lock 或临时文件权限。新版本发现此类对象、未知 owner、重解析或多重硬链接时，保留原文件和权限，报告备份无法信任并拒绝应用/恢复；helper 初始化也不再自动重写旧目录 DACL。

即使目录 owner 是 Administrators，也不能仅删除额外 ACE 后把历史 journal 的 checksum 当作可信来源证明。checksum 用于损坏检测，不能认证曾经可被其他令牌修改的内容。后续迁移必须独立授权、保留原始对象和记录、审查原值来源及完整性，再以明确步骤建立符合新边界的存储。本轮没有提供自动迁移工具，不删除空 journal 或 lock 来绕过检查，也不对现有 VPS 产物收紧、重写或清理权限。

这与核心 C02 的全树 owner / 写权限检查一致：新机器文件不引入具名账号 owner 或写 ACE；旧不可信对象的修复不应混入服务启动、只读报告或隐私开关。

## 验证

执行：`go test ./internal/privacy ./internal/privacyhost ./internal/timeprivacy -count=1`。

新增测试覆盖：SYSTEM-like / 非交互已提升 fake 环境的单项恢复和 RestoreAll、SKU / build 改变后仍恢复旧受管原值、支持系统中的机器应用、失去提升后不触碰 store / registry、HKCU 用户 manager 继续拒绝服务环境、用户 journal / 伪造位置不能进入机器恢复、异常退出与持久化失败。

Windows 写入口的令牌/位置矩阵只调用授权判断，不调用真实注册表写入。生产机器文件存储与 fake 注册表组合测试在测试临时目录验证新 directory / lock / temp / journal 的原子 SY/BA owner / ACL、只读检查、旧具名 SID 权限拒绝且 ACL / 字节保持原样、多重硬链接拒绝。临时 ACL 用例需要测试进程原本已提升，否则明确跳过；不请求 UAC、不启动 helper / GUI / 服务，不触碰真实产品目录。时区回归保持独立。

仍需在另行授权的受控机器上验收真实 SYSTEM 令牌、交互 / 替代管理员、服务身份、持久恢复与旧对象显式迁移。注册表往返成功也不等于广告、语音或剪贴板功能的运行时阻止效果，更不能作为真实隧道或流量验收证据。

## 独立交叉复核与非阻塞可用性项

独立源码交叉复核未发现新的已确认机器上下文/存储信任阻塞。一个尚未实机复现的并发可用性点：`openMachineJournal` 读句柄只允许 `FILE_SHARE_READ`，不同 helper/CLI 进程的 Report 与原子替换可能碰到 sharing violation；单实例 mutex 不跨进程。此时操作保守报错，写前失败不开始新策略写入，已有原值 journal 保留；写后记录失败仍走既有回滚/待恢复路径，不据此影响隧道。

后续可单独评估有界协调或允许已验证完整旧快照的删除共享，但必须保留 owner/ACL/普通文件/硬链接验证及恢复语义。本轮按非阻塞建议记录，没有修改 share flags 或扩大锁模型；不把未复现的并发问题写成已实测数据丢失或泄露。
