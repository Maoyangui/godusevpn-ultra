## 普通用户取消 UAC 与退出：两轮证据分开记录

两轮使用实际 Medium 会话（完整性级别 8192）、同一已安装固定 GUI 映像、无额外启动参数，并在真实 UAC 提示选择“否”。诊断器持有启动时获得的原始 Process handle，没有杀进程或用后续同名 PID 猜测退出结果。

| 检查 | 第一轮 | 第二轮 |
|---|---|---|
| 取消 UAC 后 GUI | 实际保留并可操作 | 实际保留并可操作 |
| 原始句柄等待 | 10/30/60/120 秒后仍在运行，180 秒诊断到期时仍存活 | 10/30/60 秒等待后，操作员通过托盘退出 |
| 捕获状态 | `pending_process_alive`；`exitCodeAvailable=false` | `complete` |
| 退出码 | 未取得，不能记为 0 | 原始句柄：signed `0`，hex `0x00000000` |
| 强制终止 | 无 | `processKilled=false` |
| 输出 | 捕获未完成，不推断最终输出 | stdout 0 字节；stderr 64 字节，已审读：仅一行 WebView2 环境创建成功日志 |
| 退出后补充观察 | 后续托盘退出，同名 GUI 查询为 0；该观察不补造第一轮退出码 | 同名 GUI 查询为 0，与原始句柄正常退出相互印证 |

据第二轮完整回执，本次条件下的“默认启动取消 UAC 导致崩溃”回归与托盘正常退出为**实际 PASS**。该结论不覆盖接受提权、替代管理员凭据、助手连接成功、其他授权失败类型或全部退出竞争。操作员确认 stderr 长度为 64 字节后实际审读，仅有 WebView2 环境创建成功一行，未见 panic/error；这不扩大为没有任何潜在问题。

窗口另有真实截图观察：在本次 1041 × 720 工作区最大化，随后还原为 420 × 704。它记录这次桌面上的最大化/还原和尺寸表现；多屏、其他 DPI/缩放、最小化、重载与所有首次显示时序仍未完成整体验收。

## 补充：运行中重新授权后取消

后续在已运行的普通 Medium GUI 中，操作员点击 `PrivacyAuthorize`，通过产品内确认后，在真实 UAC 提示选择“否”。GUI 仍存活，界面显示用户取消，并以红色提示“授权未完成，请手动重试”。这是运行中显式重试授权的有限 GUI 证据，与上述无参数启动诊断分开；本次未连接隧道，不证明正在运行的隧道不受影响，也不覆盖授权成功或助手连接成功。详见 [本批代理与运行中取消记录](QA11_PROXY_GUI_VM_2026-10-27.md)。
