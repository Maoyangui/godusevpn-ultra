# qa.9 普通用户 GUI 观察（2026-10-26）

本记录覆盖本次临时 Windows 11 测试桌面的有限观察。已安装包与完整文件核对见
[官方升级记录](QA9_OFFICIAL_UPGRADE_2026-10-26.md)。界面操作通过真实远程桌面完成，
未在开发机运行产品、浏览器或改变网络设置。原始截图、诊断路径和云资源信息仅保留在私有验收目录。

## 账号与启动

- 终端的完整性组读回为 Medium，后续 GUI 操作使用该普通用户会话。
- 第一次无额外参数启动已安装 GUI 时出现管理员凭据提示，选择“否”后，随后一次进程查询没有发现 GUI 进程，界面也未出现。
- 后续已正常退出上述 GUI，再由普通用户固定诊断器持有原始 Process handle 复现：空启动参数、System32 工作目录、同一已安装映像哈希；再次选择“否”后，原始进程以 `2 / 0x00000002` 退出，stdout 为 0 字节、stderr 为 853 字节，捕获完成且未终止进程。
- 原始堆栈为 `privacyhost.(*Client).Close` → `App.authorizePrivacyHost` → `startPrivacyHost`。源码复核确认：将具体类型的空 `*Client` 隐式转换为 `privacyHelper` 接口后，接口自身不为空，失败清理误调用空接收者的 Close，触发 nil pointer panic。真实取消路径在 qa.9 未通过；修复需新的候选包，不能以已有纯测试覆盖此实测失败。
- 同一已安装 GUI 使用产品现有的 `--ultra-no-elevate` 参数能够显示完整界面。这证明该条件下 WebView 与 GUI 可启动，不证明默认授权流程通过。
- 界面读回服务存在，但当前普通用户尚未注册为服务控制账号。真实隧道、浏览器授权及进程隔离不因此视为可用。

## 浏览器配置界面往返

在上述普通用户 GUI 内实际执行：

1. 打开隐私中心的浏览器保护页，编辑配置名称并保留 WebView2 内核、原生系统环境、地区与尺寸字段。
2. 点击保存，界面返回“配置已保存”，后续动作切换为保存修改、克隆和删除。
3. 刷新配置列表，实际列表显示刚保存的名称及 WebView2 内核标识。
4. 选择该项并点击载入，界面返回“配置已载入，启动时重新检查”，表单保留对应名称与环境字段。

独立只读审计器随后在同一普通用户 Medium 会话实际运行，校验当前 token、KnownFolder、
固定用户目录、只读句柄、无重解析/硬链接、目录与文件 ACL、完整 journal 哈希链和草稿 schema。
结果为 baseline pass / exit 0：1 条记录、1 帧，文件 DACL 受保护，有效授权仅当前用户、SYSTEM 和 Administrators。
原 GUI 保存后已有记录，故此 baseline 不证明创建前为空，也不证明崩溃后的持久化。

在保存该基线后，再次通过 GUI 载入同一记录。独立 `unchanged` 检查 pass / exit 0，
countDelta=0、changedRecords=0，记录内容、版本、ACL 和观察范围内同级条目保持不变。
审计器没有调用 GUI 或写入产品存储。未提供完整 GUI Record receipt，因此 receiptMatchesDisk=false；
没有提供实际秘密 canary，因此 secretCanariesChecked=0。这两项不冒充通过。
重命名、克隆、删除、跨窗口 CAS 和崩溃恢复仍未实际验收。

界面已生成可见 UA 预览；本次尚未打开独立浏览器，因此该文本不证明 HTTP、navigator、Client Hints、
iframe 或 Worker 的实际读回。代理出口与运行时保护仍使用各自的验收证据。
