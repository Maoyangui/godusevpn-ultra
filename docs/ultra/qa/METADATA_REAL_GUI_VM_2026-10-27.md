# qa.9 元数据真实 GUI 与独立文件后验（2026-10-27）

本次在隔离 Windows VM 的普通用户 Medium 会话，通过已安装的 qa.9 GUI 实际调用固定 ExifTool 13.59 后端，完成两张合成图片的读取、显式查看、七类 EXIF 逐项及组合清理。16 个新副本的独立只读文件核对全部通过；取消保存与拒绝覆盖也经真实 GUI 观察。**这是该版本、该会话和两张合成图片的有限验收，不是全部元数据格式或新包 GUI 的验收。**

安装身份及已有启动限制分别见 [qa.9 官方升级](QA9_OFFICIAL_UPGRADE_2026-10-26.md) 和 [普通用户 GUI 有限观察](QA9_ORDINARY_GUI_OBSERVATIONS_2026-10-26.md)。本次数据页成功不改变 qa.9 默认启动取消 UAC 已复现崩溃的事实，也不证明机器助手、独立浏览器或隧道保护通过。

## 输入与真实 GUI 操作

仅使用自行生成的两张夹具，没有扫描个人目录，也未使用真实照片或真实 GPS 信息：

| 输入 | 尺寸 | 输入大小 | 范围 |
|---|---|---:|---|
| 合成 JPEG | 4 × 3 | 1340 字节 | 含七类固定 EXIF 测试字段 |
| 合成 PNG | 4 × 3 | 771 字节 | 含相同七类 EXIF 测试字段 |

GUI 默认预览只显示字段类别和数量，没有默认展示实际值。显式选择作者字段并请求查看后，显示的值仅为合成文本 `QA Synthetic Artist`。没有将经纬度、序列号、文件绝对路径或字段值写入公开证据。

操作员分别对 JPEG 和 PNG 执行以下八种选择并通过原生保存对话框生成新副本；每次 GUI 的 `removed` 后验与该次选择相符：

| 选择 | 字段 ID | JPEG | PNG |
|---|---|---|---|
| 作者 | `artist` | 通过 | 通过 |
| 版权 | `copyright` | 通过 | 通过 |
| 描述 | `description` | 通过 | 通过 |
| 软件 | `software` | 通过 | 通过 |
| 相机信息 | `camera` | 通过 | 通过 |
| 拍摄时间 | `capture-time` | 通过 | 通过 |
| EXIF GPS | `exif-gps` | 通过 | 通过 |
| 同时选择上述七类 | 全部七类，不是任意格式的全量清除 | 通过 | 通过 |

真实失败路径另作观察：

- 在保存对话框取消后，原预览保留，没有显示清理成功。
- PNG 选择预先存在的目标文件，并在 Windows 替换确认中选择“是”后，产品后端仍以红字拒绝覆盖。Windows 对话框的确认没有绕过后端仅新建文件的约束；独立文件哈希核对确认该既有目标没有改变。

## 独立只读核对

实际在远端运行的独立检查器只读取夹具基线、源文件、16 个预期副本和既有目标。它使用独立的 Go 图像解码与 EXIF 类别解析，不调用 ExifTool、生产适配器、产品桥或 GUI，也不代替操作员执行清理。

结果为 `VERIFY_EXIT=0`：

- `allExpectedCopiesPassed=true`；16 个用例的 `exists`、`sourceUnchanged`、`pixelsUnchanged`、`selectionVerified` 全部为 true。
- 源 SHA256 与清理前基线一致；副本解码像素与各自源基线一致。
- 对这两张夹具检查七类 EXIF 的存在性：选中类别已不存在，未选类别仍存在。这不升级为独立证明每个保留 tag 的所有值或所有隐藏块均相同。
- `existingDestinationUnchanged=true`，既有目标字节未变。
- `adapterExecutedByVerifier=false`；`uiAcceptanceRequired=true` 保持原值。GUI 选择、默认不显示值、显式查看、取消与红字拒绝来自实际界面观察，不能单靠文件检查器推断。

完整 JSON 结果已在 VM 以 UTF-8、CreateNew 方式单独保存。原始截图、账户和 VM 标识、输入/输出绝对路径以及原始报告只留在私有验收材料中，不随公开源码或发行包附带。本记录依据操作员的真实 GUI 观察、实际远端检查结果及私有结果截图；没有在开发机重新运行产品、ExifTool 或该 VM 检查器。
