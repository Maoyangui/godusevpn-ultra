# QA11：首次真实 Chrome 启动未通过

## 已观察事实

本次为隔离 Windows VM、普通用户 GUI 与跨账户 UAC 管理员助手；使用此前官方完整升级并逐文件核验的 QA11。包未因后续 QA12 源码修改而重建。

- 在真实 GUI 从 Google 官方目录下载 Chrome for Testing `158.0.8125.0`。GUI 返回 305 个文件及树/版本读回匹配；本次尚未独立审计该缓存树。
- 使用用户提供的独立 SOCKS 代理；同页主动代理探测曾成功，错误认证探测曾失败。该探测不能证明浏览器出口。
- 本次浏览器使用原生环境和默认硬件配置。UAC 同意后 GUI 显示助手连接；这不能证明浏览器 guard factory 已成功。
- 点击启动后先显示准备中，随后显示浏览器已退出、网络规则清理未确认。没有观察到可用浏览器窗口。
- 操作者随后只点击了一次关闭，返回固定错误 `BROWSER_ENGINE_OPERATION_REFUSED`，清理状态仍未知。未重复启动或关闭。
- 在普通用户 PowerShell 只读查询：`chrome` 进程数为 0；已安装 GUI、其授权助手子进程及服务仍存在。查询未读取命令行、代理认证或助手会话秘密。

## 判定与保留状态

本次实际启动失败，不能声明 Chrome 可用、UA/出口正确或隔离通过。进程数为 0 只证明查询时未发现 Chrome，不证明 WFP 过滤器已经移除。

源码复核发现 guard 安装前期拒绝也可能在后续 Remove 中得到 unknown；因此这条 GUI 文案本身不证明过滤器曾安装成功，也不能确定原始失败阶段。

## 随后取得的独立只读证据

在保留 GUI/助手进程的情况下，以同一个助手管理员账户运行单独的只读诊断程序。诊断核对了已安装映像哈希、账户、会话、父子关系、创建时间和存活状态；完整原生 JSON 回执通过 VM Run Command 只读取回，`identityVerified`、`completed`、`processesStableAndAlive`、`receiptWritten` 均为 true。

- 父 GUI 的有限查询句柄打开成功；增加 `PROCESS_DUP_HANDLE` 后，以与实际 guard 相同的访问掩码打开失败，Win32 返回 5（访问被拒绝）。
- GUI 为普通用户 Medium，助手及诊断工具为另一账户的已提升 High；工具与助手的 SeDebug 权限存在但未启用。诊断没有调整权限、令牌或进程 DACL。
- 普通查询和 impersonate 权限的父进程 token 都可打开，使用这些 token 查询用户 LocalAppData 成功；由于额外进程句柄打开失败，没有尝试依赖该句柄的 token 复制路径。
- 固定浏览器 provider 的四个相关 ALE 网络层枚举全部完成，过滤器计数为 0。此结论限于本次查询的 provider、网络层和时点，不代表全系统无过滤器，也不证明历史浏览器流量已受保护。

额外进程句柄拒绝已在同一条实际权限路径复现；旧助手未记录最初 factory 错误，因此不把此次独立返回码冒称为旧助手曾记录的返回码。QA12 将保留最初失败阶段，并仅在完成身份核对后处理所需的确切权限。修复仍须重新进行实际浏览器启动、出口、UA、隔离和清理验收，不能由新的文案或纯测试追认为通过。

首版诊断工具曾因自身 token 缓冲区探测假设错误在 stage 30 / Win32 24 退出；该工具失败不归因于产品。第二版修复有界缓冲区处理后才取得上述完整回执。
